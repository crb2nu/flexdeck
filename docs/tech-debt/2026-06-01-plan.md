## Backlog-Ready Slices

### TD-018: Cover agents API handlers (CRUD + edge cases)  — TOP SLICE

- Problem: all 19 handler funcs in `internal/api/handlers/agents.go` are at 0% coverage despite being operationally meaningful CRUD/registry endpoints.
- Approach: build `&Handler{cfg, agentsRegistry}` with a `t.TempDir()`-backed `agents.NewRegistry`, then table-driven `httptest` requests through a `chi` router for URL params.
- Acceptance criteria:
  - AgentsList: empty registry returns `{"agents":[]}`; populated returns registered agents.
  - AgentsGet: existing id returns the agent; unknown id returns 404.
  - AgentsCreate: disabled cfg returns 503; invalid JSON returns 400; missing id/name/url returns 400; duplicate id returns 409; valid returns 201 and defaults Type to langgraph.
  - AgentsUpdate: disabled 503; invalid JSON 400; unknown id 404; valid 200.
  - AgentsDelete: disabled 503; unknown id 404; valid 200.
  - AgentsGraph: empty graph; `depends_on` metadata produces an edge; edge to unknown dependency is dropped.
  - AgentsHealth (empty registry) and the proxy handlers' disabled path (CheckHealth/Test/Invoke/ExternalFrameworks).
- Outcome (shipped): agents.go's 19 zero-coverage funcs became 11 covered network-free handlers (AgentsCreate/Update/Delete 100%; Graph/List/Get/Health 55-72%), lifting `internal/api/handlers` from 29.8% to **31.5%**. The 8 remaining 0% funcs are live-proxy handlers (Stream/Usage/BuilderChat/BuilderInfo/DifyChat/LangGraphRun/HUDAgentSessions/LangGraphListAssistants) deferred to TD-023's fake-upstream pass. A flat +5pp package target was unrealistic for a single 690-line file in a ~12k-line package; the meaningful win is eliminating the largest zero-coverage cluster.
- Verification: `go test ./internal/api/handlers -cover`; `go test ./...`.
- Rollback/safety: test-only; no production code changes. Construct registry on a temp path so no real registry file is touched.
