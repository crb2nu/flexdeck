## Wave Plan

### Wave 1 (Quick Wins / High Leverage)

Scope:
- TD-001 Re-enable backend CI tests.
- TD-007 Implement `UI_CONFIG_DIR` loading for `/api/ui/config`.
- TD-002 Slice A: add baseline tests for `internal/config` and `internal/cache`.

Dependencies:
- None external; can execute within this repository.

Constraints:
- Keep CI runtime increase under agreed MR threshold.
- Preserve current API behavior for `/api/ui/config` fallback.

Not in this wave:
- Frontend visualization decomposition.
- API client domain split.

Exit criteria:
- MR pipelines execute backend tests on `main` and merge requests.
- UI config endpoint reads configured file with safe fallback.
- Baseline tests in config/cache run in CI and pass.

### Wave 2 (Medium Effort / High Risk-Reduction)

Scope:
- TD-002 Slice B: extend tests to `internal/k8s`, `internal/metrics`, `internal/models`.
- TD-004 Introduce shared polling scheduler and migrate highest-frequency panels first.
- TD-006 Split router registration by domain module while preserving route paths.

Dependencies:
- Wave 1 CI guardrails in place.

Constraints:
- Do not introduce route-level breaking changes.
- Do not increase polling latency for critical dashboards.

Not in this wave:
- Deep HoloDeck/TopologyGraph architecture refactor.
- Full API contract/client re-architecture.

Exit criteria:
- Targeted backend package coverage floor met.
- Polling manager in place with migrated top polling call sites.
- Router modularization merged with route smoke tests green.

### Wave 3 (Strategic Refactors Requiring Coordination)

Scope:
- TD-003 Decompose `TopologyGraph` and `HoloDeck` into isolated layout/render/interaction modules.
- TD-005 Split `web/src/lib/api.ts` into typed domain clients and reduce fallback parsing paths.

Dependencies:
- Wave 2 stabilizes routing and polling behavior.
- Frontend/backend agreement on normalized contract boundaries.

Constraints:
- Maintain existing feature parity and route compatibility.
- Keep large-topology UX responsive during incremental rollout.

Not in this wave:
- New product feature development unrelated to stability/performance.

Exit criteria:
- Large-topology benchmark improved by at least 30% vs current baseline.
- API client split complete with contract tests and no net increase in production errors.

## Backlog-Ready Slices

### TD-001: Re-enable backend test stage in CI
- Status (2026-02-19): Implemented on branch `codex/backlog-phase35-hud-degraded-ux` (pending CI verification).
- Impact notes:
  - `test:backend` now runs on merge requests and `main` instead of being permanently disabled.
  - Job now performs repository checkout in `before_script` to work with `GIT_STRATEGY: none`.
  - Coverage output is persisted as a pipeline artifact (`coverage.out`).
- Problem statement: Backend test job exists but is disabled (`when: never`), so merge pipelines do not guard backend regressions.
- Acceptance criteria:
  - `test:backend` runs for merge requests and `main`.
  - Job publishes coverage artifact and fails pipeline on test failure.
- Verification:
  - Run one MR pipeline and one `main` pipeline, confirm job execution and report.
- Rollback/safety:
  - Revert rules change if pipeline load is unacceptable; keep job manual while investigating runtime bottlenecks.

### TD-007: Implement `UI_CONFIG_DIR` loading
- Status (2026-02-20): Merged via MR `!8` (commit `a294a8e` on `main`).
- Problem statement: `/api/ui/config` ignores configured `UI_CONFIG_DIR` and returns hardcoded values.
- Acceptance criteria:
  - Endpoint loads and validates file-based UI config when present.
  - Falls back to defaults if missing/invalid, with warning logs.
- Verification:
  - Integration test with valid/invalid/missing config files.
- Rollback/safety:
  - Guard feature behind fallback path; hardcoded default remains safe fallback.

### TD-002A: Baseline tests for `internal/config` and `internal/cache`
- Status (2026-02-20): Implemented on branch `codex/td-002a-config-cache-tests` via MR `!9` (pipeline `1795` green; pending merge).
- Impact notes:
  - Added deterministic env/default/validation tests for `internal/config` (`config_test.go`).
  - Added cache read/write/expiry/invalidation and `GetOrFetch` behavior tests for `internal/cache` (`cache_test.go`) using in-memory Redis.
  - `go test ./... -cover` now reports non-zero coverage for both packages.
- Problem statement: Critical runtime config/cache behavior has no direct tests.
- Acceptance criteria:
  - Add deterministic unit tests for env parsing/default behavior and cache read/write/expiry semantics.
- Verification:
  - `go test ./... -cover` shows non-zero coverage for both packages.
- Rollback/safety:
  - Tests only; no runtime behavior changes.

### TD-002B: Expand tests for `internal/k8s`, `internal/metrics`, `internal/models`
- Problem statement: Integration-heavy packages currently have 0% coverage and high regression risk.
- Acceptance criteria:
  - Add parser/transform and error-path tests for representative flows.
  - Establish initial package-level coverage floor.
- Verification:
  - Coverage report reflects target floor on these packages.
- Rollback/safety:
  - Introduce fixture-based tests first; no behavior change rollout required.

### TD-004: Shared polling scheduler
- Problem statement: 25 interval loops create fragmented refresh semantics and unnecessary load.
- Acceptance criteria:
  - Shared scheduler supports interval registration, visibility pause, and backoff.
  - Migrate top 5 highest-frequency polling call sites first.
- Verification:
  - Compare network request counts before/after on dashboard/model routes.
- Rollback/safety:
  - Keep per-component fallback polling path under feature flag during rollout.

### TD-006: Router modularization
- Problem statement: Single router file with high route density/churn increases routing and middleware drift risk.
- Acceptance criteria:
  - Route registration moved into domain modules with explicit middleware composition.
  - Route smoke tests assert expected route/method availability.
- Verification:
  - Existing API tests plus new smoke tests pass.
- Rollback/safety:
  - Preserve existing route paths and middleware behavior; revert by module if regressions appear.

### TD-003: Visualization decomposition and perf hardening
- Problem statement: Large monolithic visualization components are expensive to change and correlate with high benchmark latency at scale.
- Acceptance criteria:
  - Extract layout engine and render/update loops into smaller modules.
  - Reduce large-topology layout benchmark time by >=30%.
  - Maintain feature parity for interactions and overlays.
- Verification:
  - `npm run perf:topology` tracked before/after; targeted UI smoke checks pass.
- Rollback/safety:
  - Phase rollout behind feature flags or route-level fallback to current renderer.

### TD-005: API client split + contract tightening
- Problem statement: `api.ts` centralizes many endpoints and `any` payloads, while fallback parsing masks contract drift.
- Acceptance criteria:
  - Split into domain clients with typed response contracts.
  - Add contract tests for HUD/FlexInfer normalization.
  - Reduce fallback parsing usage to documented transitional paths.
- Verification:
  - Typecheck/test coverage for client modules and contract suites.
- Rollback/safety:
  - Keep compatibility adapters for one release cycle before removing legacy parsers.

## Explicit Out-of-Scope
- New feature development unrelated to reliability/performance/maintainability debt.
- Cross-repository contract redesign requiring upstream changes outside FlexDeck.
- Infrastructure migrations not required to close listed debt items.
